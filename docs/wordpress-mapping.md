# Перенос демо в WordPress

Статический фронтенд служит визуальным эталоном: разметку компонентов, CSS и клиентский JavaScript можно перенести в тему WordPress без смены дизайна. При интеграции тестовые данные заменяются выводом WooCommerce и ACF.

## Целевая архитектура

- Собственная лёгкая тема сохраняет текущую DOM-структуру и классы. Blocksy/Floreo используется как визуальный ориентир, но не как обязательная техническая зависимость.
- WooCommerce работает в режиме каталога и хранит товары, категории, атрибуты, цены и изображения.
- ACF добавляет только B2B-поля, которых нет в WooCommerce: минимальный тираж, срок, совместимые нанесения и отраслевые сценарии.
- Небольшой плагин проекта регистрирует кейсы и виды нанесения, чтобы бизнес-данные не исчезали при смене темы.
- Плагин формы принимает заявку, файл макета и выбранный товар; отправка из статического прототипа намеренно демонстрационная.

## Что переносится без перерисовки

| Сейчас | В теме WordPress |
| --- | --- |
| `src/assets/css/styles.css` | тот же CSS-файл темы |
| `src/assets/js/main.js` | тот же клиентский JavaScript; фильтры получают данные WordPress |
| `src/assets/images/` и шрифты | медиатека или статические assets темы |
| Nunjucks-компоненты | PHP template parts с той же HTML-разметкой и классами |
| JSON-циклы и переменные | WooCommerce/WordPress Query и ACF-поля |

Таким образом, при интеграции переписывается серверная подстановка данных, а не внешний вид. Контрольный критерий — одинаковые DOM-структура, CSS-классы и набор состояний на статическом и WordPress-стенде.

| Статический элемент | WordPress / WooCommerce |
| --- | --- |
| Шапка, подвал, навигация | Части шаблона темы и меню WordPress |
| Карточка и страница товара | `product` WooCommerce, шаблоны архива и товара |
| Категории каталога | `product_cat` |
| Цвет, размер, материал, плотность | Атрибуты WooCommerce; ACF только для нестандартных полей |
| Галерея, цена, артикул | Штатные поля товара WooCommerce |
| Минимальный тираж, сроки, способы нанесения | Группа полей ACF у товара |
| Блоки главной и общие контакты | ACF Blocks/поля страницы и ACF Options Page |
| Кейсы и примеры работ | Отдельный тип записи `case` с ACF |
| Виды печати | Отдельный тип записи или таксономия; выбор зависит от требуемых страниц архива |
| Форма расчёта | Плагин формы с загрузкой файла и привязкой выбранного товара |

## Правила совместимости

- Сохранять семантическую HTML-разметку и независимые CSS-классы компонентов.
- Не связывать интерфейс напрямую с форматом тестовых JSON-данных: шаблон получает нормализованные поля товара.
- Все изображения и ссылки выводить через функции WordPress, а динамический текст экранировать.
- Повторяющиеся блоки оформлять как шаблонные части или серверные ACF Blocks.
- Каталог, фильтры и вариации строить на API WooCommerce, не дублируя товарную модель в ACF.

## Соответствие шаблонов

| Статический шаблон | Шаблон WordPress |
| --- | --- |
| `layouts/base.njk`, `header.njk`, `footer.njk` | `header.php`, `footer.php` и общая обвязка темы |
| `index.njk` | `front-page.php` |
| `catalog/index.njk` | `archive-product.php` |
| `products/product.njk` | `single-product.php` / WooCommerce template override |
| `cases/index.njk` | `archive-case.php` и `single-case.php` |
| `printing/index.njk` | архив и запись типа `print_method` либо шаблон страницы |
| `about`, `contacts`, `quote` | именованные page templates |

## Условия точного переноса

1. Не пересобирать утверждённые страницы внутри визуального конструктора: тема должна выводить зафиксированные компоненты.
2. Сначала создать модель данных WooCommerce/ACF, затем подключать её к уже готовым шаблонам.
3. Изолировать стили сторонних плагинов, чтобы они не меняли типографику, кнопки и поля формы.
4. Сравнить статический и WordPress-стенд на одинаковых контрольных ширинах до публикации.
5. После приёмки менять контент через админку, а структуру компонентов — через версионируемый код темы.

При соблюдении этих условий внешний вид переносится один к одному; основная интеграционная работа состоит в замене источника данных, подключении административных полей и реальной обработке формы.
